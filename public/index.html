SAFE RESET & DATA MANAGEMENT OPERATIONS

Each tier strictly scopes what data is impacted. Historical data is never silently removed.

1. CLEAR LOCAL DASHBOARD STATE

Resets local UI filters, search query inputs, and cached browser display without touching the backend.

2. CANCEL SELECTED CRAWL JOB

Marks the selected job CANCELLED and discards remaining queued tasks belonging only to that job.

3. FLUSH PENDING FRONTIER QUEUE

Clears pending tasks and leases in Redis. Preserves all PostgreSQL indexed pages and domain metrics.

4. PURGE SELECTED JOB DATA

Deletes the selected job, its seeds, errors, and crawled pages from PostgreSQL without affecting other jobs.

5. PURGE ALL INDEXED PAGES DATA

Clears crawled pages and domain statistics while keeping job records and worker fleet telemetry.

6. FULL DEVELOPMENT RESET

Clears local Redis frontier, jobs, events, and database tables cleanly for a fresh dev test run.

7. ADMINISTRATIVE PRODUCTION RESET (DISABLED BY DEFAULT)

Requires ENABLE_PRODUCTION_RESET=true, valid admin authorization, and typing WIPE ALL DATA.

ARCHITECTURE, WORKER ONBOARDING & REST API

Complete technical documentation for distributed cluster operation and security

Dual Deployment Modes

  • Mode A — Distributed Cluster: Go Coordinator Master (cmd/master), independent Go Worker Daemons (cmd/worker), Redis Frontier with 60s atomic task leases, and PostgreSQL relational index with GIN full-text search.
  • Mode B — Serverless Preview: Bounded Node.js Vercel functions executing on-demand SSRF-validated HTTP fetches cleanly labeled as Preview Mode when no Go coordinator is attached.

Launching Real Distributed Workers

docker compose up -d --build
docker compose up -d --scale worker=3
# Or locally with Go:
go run cmd/master/main.go
go run cmd/worker/main.go -master http://localhost:8080 -concurrency 4
