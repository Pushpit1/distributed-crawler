TIERED DATA MANAGEMENT & RESETS

Choose the appropriate reset level. Irreversible operations require explicit confirmation phrases.

LEVEL A: CLEAR LOCAL UI STATE

Clears local search filters and browser cache. Preserves backend database and queue.

LEVEL B: PURGE FRONTIER QUEUE

Flushes pending Redis crawl tasks and leases. Preserves all indexed pages and domains.

LEVEL C: PURGE CRAWLED PAGES DATA

Truncates crawled_pages and domain stats. Preserves worker registrations and crawl jobs.

LEVEL D: FULL PRODUCTION RESET

Completely purges database, Redis frontier, events, and re-seeds starter URL. Requires typing confirmation phrase.

SYSTEM ARCHITECTURE & API REFERENCE

Technical overview of distributed components, task leasing, and REST endpoints

Distributed Architecture Overview

The platform separates coordination, persistence, and network fetching into discrete components:

  • Coordinator Master: HTTP API handling job submissions, domain politeness delays, task leases, and search queries.
  • Redis Frontier: High-throughput FIFO queue (`LPUSH`/`RPOP`) with atomic deduplication (`SADD`) and in-flight visibility leases (`HSET`/`HDEL`).
  • PostgreSQL Index: Relational storage storing pages, canonical URLs, HTML headers, and GIN-indexed Full-Text vectors (`tsvector`).
  • Distributed Workers: Autonomous Go daemons with SSRF defense, `robots.txt` caching, and automatic heartbeats.
